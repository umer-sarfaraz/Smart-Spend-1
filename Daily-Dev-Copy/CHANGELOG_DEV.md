## 2026-08-21 (b) — Design-system unification: one palette, 401 colour references, and the deleted `CAT_GRAD` duplicate

**Out-of-band pass, requested by Umer** (not part of the daily rotation). Trigger: after
the PWA packaging work, Umer's read of the app was *"it looks like HTML kind of thing,
some widgets are misplaced"* — and a friend suggested rebuilding the frontend in React.

- **The framework question, settled:** the app **is already React** (React 18 + Vite, 11
  components). The friend most likely meant *React Native*, a different thing — and it
  would not have fixed this. The diagnosis below is a token problem, not a framework
  problem; in React Native the same 44 colours would have been rewritten by hand into
  StyleSheets and carried across unchanged.
- **Found wrong:** the app was running **two rival palettes** and the wrong one was
  winning. Against DESIGN_DIRECTION.md's violet/teal/grey-ramp spec, a leftover Tailwind
  slate+indigo+emerald set held **182 uses to the spec's 58**:

  | In code | Uses | Should be |
  |---|---|---|
  | `#64748b` slate-500 | 84 | `#5A6270` tertiary |
  | `#94a3b8` slate-400 | 49 | `#8A93A0` secondary |
  | `#10b981` emerald-500 | 42 | `#34D399` teal |
  | `#6366f1` indigo-500 | 50 | `#A99BFA` violet accent |

  Worse, `App.css` already had a **`:root` token block** — it just pointed at the
  Tailwind values (`--primary: #6366f1`, `--emerald: #10b981`, `--slate-text: #94a3b8`),
  so the tokens were actively propagating the wrong palette. And **710 inline
  `style={{…}}` blocks vs 218 CSS classes** meant most colours bypassed tokens entirely.
- **The real find — a second category palette:** `Dashboard.jsx` carried its own
  `CAT_GRAD` map, a hand-copied duplicate of `CATEGORIES` in `utils/parser.js`, and the
  two **had already drifted**: dining was orange on Home but **pink** everywhere else;
  dairy grey on Home but **blue** elsewhere; fuel and utilities likewise. The same
  category was a different colour on Home than in History, Reports or Settings. This is
  the single most likely cause of the "widgets look misplaced" read — same fact, two
  colours, depending on the screen.
- **Changed:**
  - **`src/App.css` (116 refs)** — the `:root` block now holds spec values:
    `--primary #A99BFA`, `--emerald #34D399`, `--slate-text #8A93A0`,
    `--white-text #F4F6F8`, `--bg-deep #0B0E13`, `--bg-dark #141921`, and every
    `rgba(99,102,241,…)` / `rgba(16,185,129,…)` alpha form remapped with alpha preserved.
  - **All 11 components + `App.jsx` + `utils/` (285 refs)** — text ramp, accent and
    surface colours mapped onto the spec. Gradient partner shades are **derived from the
    spec colours by moving lightness only** (`#715AF7` violet-deep, `#CDC5FC`
    violet-light, `#239F72` teal-deep), so nothing off-hue was invented.
  - **`src/utils/parser.js`** — the five categories DESIGN_DIRECTION names explicitly now
    use its exact values: produce green `#97C459`, meat coral `#E8896B`, dining amber
    `#EF9F27`, fuel blue `#5BA3E8`, other gray `#9AA3AF`, each with an on-hue gradient.
    The other nine keep their hues; all 14 verified still distinct.
  - **`src/components/Dashboard.jsx`** — **`CAT_GRAD` deleted**; the Breakdown bar reads
    `info.color` (i.e. `CATEGORIES[cat].color`) like every other screen. **−7 lines.**
  - **Deliberately protected:** `ACCENT_COLORS` in `profiles.js` (a user-pickable
    preference list — remapping it would collapse choices and silently change saved
    prefs) and the two state colours (`#f43f5e` over, `#f59e0b` at risk).
  - Two collisions were caught and avoided before applying: a blanket map would have made
    `vegetables`/`shopping` and `dairy`/`other` **identical**, which is why category
    colours were handled explicitly rather than swept.
- **Build:** ✅ Passed (`vite build`, clean, 2284 modules, 6.09s) — verified in the Linux
  sandbox (`/tmp/db2`). Spec colours went from **58 → 324 uses**; the four dominant
